## Objective

Pin the KB search panel's **request wiring** and its **user-visible states** with frontend
assertions, so a param-name drift against the backend probe or a state regression fails the suite
instead of shipping silently.

## Problem (verified in code)

`SearchPanel` owns a `runSearch` that calls `searchKb({ q, topK, minSim })`, and `searchKb` builds
`/panel/api/kb/search?q=…&top_k=…&min_sim=…`. Those snake_case names are **the backend probe's
contract** (`app/panel/api/routes/kb.py:78-85`), so the frontend and the backend are coupled by a
string that nothing tests. The panel also renders five non-idle states:

| State | Rendered as |
|---|---|
| `loading` | `StateMessage` role `status`, title "Buscando en la base de conocimientos" |
| `ready` | summary "N resultados ordenados por similitud." + results `DataTable` |
| `empty` | `EmptyState` title "No encontramos resultados" |
| `error` | `StateMessage` role `alert`, title "No pudimos realizar la búsqueda" |
| `denied` | `StateMessage` role `alert`, title "No tienes permiso para buscar en la base de conocimientos" (only when `ApiError.status === 403`) |

None of it is asserted today. A rename of `top_k`, a dropped `min_sim`, a swallowed 403 or a
collapsed empty state would all pass the current 602-test suite.

## Decisions

**A — assert the request contract, not just the render.** The first assertion pins the `fetch` URL to
`/panel/api/kb/search` carrying `q`, `top_k` and `min_sim`. That is the string that couples this panel
to `app/panel/api/routes/kb.py:78-85`, and it is the one thing a rename breaks silently.

**B — cover the five non-idle states.** They are the panel's observable surface, and `denied` in
particular is the only path that distinguishes an `ApiError` with `status === 403` from a generic
failure. Covering only the happy path would leave that branch unproven.

## Acceptance criteria

1. A new `describe` block asserts the search request wiring: the URL carries `q`, `top_k` and
   `min_sim` with the values the form holds, and reflects a change to the `Máximo de resultados` and
   `Similitud mínima` inputs.
2. The five non-idle states are each asserted through their real role and visible text: `loading`,
   `ready` (summary count + rows), `empty`, `error`, and `denied` (403).
3. `cd web && npm test` is fully green with the new tests included, and the file count does not drop.
4. `git diff --name-only` shows **only** the test file. Zero production diff.
5. Every new assertion has a recorded mutation proof (behavior broken → that assertion failed →
   mutation reverted).
