## Specs

- **S1.** `conversations.list` and `conversations.search` MUST return an explicit projection, never a database row: `id`, customer name, phone, state, a shortened summary and the last message time. Owner's words for the field list: "id, cliente, teléfono, estado, summary corto, último mensaje". Measured on seeded data, 12 conversations cost 4,090 characters today (341 per row, twelve columns including `captured_data`) and the tool's own `limit` allows 20 — about 6,800, more than the whole evidence budget.
- **S2.** `conversations.transcript` MUST bound each message body and the whole result with a visible truncation marker, and MUST NOT drop a message or an event. The detail of one conversation is what the listing points at, so it cannot become a listing-sized payload.
- **S3.** The budget relation MUST be a test, not a comment, for the tools this unit measures: `conversations.list` and `conversations.search` at their maximum page stay inside `_LISTING_EVIDENCE_SHARE` of `_TOOL_EVIDENCE_LIMIT`, the transcript stays inside `_DETAIL_EVIDENCE_SHARE`, no conversation tool returns a raw database row, and the stale comment in `app/chat/assistant/tools/fetch.py:33` stops citing `_TOOL_EVIDENCE_LIMIT (4,000)` while the constant is 5,500. Owner's words: "Ningún resultado de tool puede ocupar más de ~40 % de la caja de evidencia, y ningún tool del asistente devuelve una fila cruda de la base." The shares in `app/chat/assistant/nodes.py` are 45 % for a listing (two must coexist in one turn) and 78 % for a detail tool (it is the turn's answer; a maximal transcript spends its structure on row keys and timestamps and leaves little else), and every size derives from those constants rather than from a literal.
- **S4.** The ceiling does not move. `_TOOL_EVIDENCE_LIMIT` stays at 5,500, `web.fetch` keeps its own `MAX_PAYLOAD = 3_600`, pagination (`limit`/`offset`, `MAX_ITEMS = 20`) is untouched, and the panel API is untouched: `list_conversations` has exactly one caller, the assistant tool, and the panel reads through its own serializers. Owner's words: "No se sube el techo… No se toca `web.fetch`… No se toca la paginación… No se toca el panel".
- **S5.** The delivery route stays the one already approved for this repository: worktree, ODD doc, observed RED before the implementation, `quick` per iteration, `full` at closure, then a PR for the owner. Owner's words: "Sí, arrancá con todo el flujo".
