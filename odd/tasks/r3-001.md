## Objective

Make the admin KB retrieval probe reject an out-of-range `top_k` or `min_sim` **at the boundary**,
instead of silently executing a query whose meaning the caller did not intend.

## Problem (verified in code)

`app/panel/api/routes/kb.py:78-85` declares both parameters with no bounds:

```python
top_k: int = kb_service.DEFAULT_TOP_K,
min_sim: float = kb_service.DEFAULT_MIN_SIM,
```

- **`top_k` becomes a SQL `LIMIT`** (`app/services/kb.py:362-367`, `order_by(distance.asc()).limit(top_k)`).
  `top_k=0` emits `LIMIT 0` and silently returns an empty ranking; `top_k=-1` is **a 500**, not an
  unbounded scan: psycopg validates the row count on the client and raises
  `psycopg.errors.InvalidRowCountInLimitClause: LIMIT must not be negative`. A large value brute-forces
  the whole matching corpus.
  *(Corrected during implementation. Both the handoff and the first read of the code assumed
  `LIMIT -1` meant "no limit" in PostgreSQL and labelled that as inference; the RED run showed the
  crash instead, and a direct `SELECT 1 LIMIT -1` against the test database reproduced it.)*
- **`min_sim` is a cosine similarity floor**, not a distance: the query filters
  `distance <= 1 - min_sim` and returns `1 - distance` (`app/services/kb.py:350-367`). Its domain is
  `[-1, 1]`. `-1.0` permits the full ranking (this is the floor the calibration harness relies on);
  `0.0` deliberately cuts the negative-similarity tail; `2.0` matches nothing. A value outside the
  domain is not an error the caller ever sees — it just quietly changes the measurement.

Reachability is admin-only (`require_admin_json`, `app/panel/api/deps.py:58-62`), so this is a
correctness and consistency hole, not a privilege escalation: the probe accepts nonsense and returns a
plausible-looking ranking for it.

Type coercion is already handled by FastAPI (`?top_k=abc` is a 422); what is missing is the range.

## Decisions

**A — `top_k` is bounded `ge=1, le=50`.** `ge=1` because 0 and negatives *are* the hole: `top_k=0`
silently returns an empty ranking and `top_k=-1` crashes the request with a psycopg 500. `le=50`
because that is the ceiling this repo already puts on the same service's retrieval path
(`app/panel/api/routes/chat.py:72`), and `DEFAULT_TOP_K` is 5, so 50 is ten times the default head.
`conversations.py:215` allows 100, but that is a *list* endpoint; a ranked retrieval probe is better
matched by the chat limit.

**B — `min_sim` is bounded `ge=-1.0, le=1.0`.** That is the domain of cosine similarity as this query
uses it. The lower bound must **not** be raised to `0.0`: `-1.0` is the deliberate "rank everything"
floor used to calibrate retrieval (`odd/tasks/kb-retrieval-calibration.md`), and `0.0` would cut the
negative tail and silently change what the probe can measure.

## Acceptance criteria

1. `top_k=0`, `top_k=-1` and `top_k=51` are rejected with **422** and are no longer executed.
2. `min_sim=-2` and `min_sim=2` are rejected with **422**.
3. In-range values behave exactly as before: `top_k=1`, `min_sim=0` and `min_sim=1` keep passing.
4. No 500s, and no change outside the probe's boundary check.
