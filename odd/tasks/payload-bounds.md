## Specs

- **S1.** `read_project_file` MUST page inside the evidence budget instead of above it, and its continuation cursor MUST survive any truncation. Owner's words: "es importante que si el asistente necesita leer un archivo lo lea completo. y que no se corte. no se puede truncar a mitad. debe ser posible leerlo completo." Concretely: the tool's page `limit` defaults within the detail share (`_DETAIL_EVIDENCE_SHARE * _TOOL_EVIDENCE_LIMIT`, ~4,290) and its maximum is that same bound; the payload puts `kind`, `chars`, `offset`, `next_offset` and `truncated` **before** `text`, because a truncation eats the tail and today it eats the cursor with it, leaving the model unable to continue. `app/services/project_files.py::MAX_FILE_TEXT_CHARS` stays at 20,000: the panel reads through its own defaults and this unit does not change it.
- **S2.** Reading a file MUST be autonomous. Owner's words: "me parece bien si puede leer un archivo por partes. pero lo deberia hacer autonomamente, no consultar por confirmacion." Read-only tools already run without approval; what is missing is the instruction. `agent/prompts/assistant_plan.md` MUST tell the planner that a `next_offset` that is not null means the file continues, that it continues reading without asking the operator, and that when its steps run out it reports how much it read (`offset` of `chars`) instead of claiming the file was read.
- **S3.** `project.list` and `project.find` MUST return an explicit projection instead of a raw `Project` row: `id`, `slug`, `name`, short `purpose`, `created_at`. Measured through `_plain` at ~365 characters per raw row, so ten rows already exceed a listing's share. `list_project_files` already projects and only needs the guard.
- **S4.** When a single payload still cannot fit the box, `_render_tool_evidence` MUST cut it with an explicit marker naming how many characters were dropped. Owner's words: "no se puede truncar a mitad". The emergency brake stays — the marker is what makes it honest instead of silent.
- **S5.** One guard MUST cover every tool whose payload grows with data — `read_project_file`, `project.list`, `project.find`, `list_project_files`, `web.search`, `web.fetch`, `customers.list`, `customers.search`, `appointments.upcoming`, `conversations.list`, `conversations.search`, `conversations.transcript`, `assistant.capabilities` — asserting each one's widest legal payload stays inside its share, with every size derived from `_TOOL_EVIDENCE_LIMIT` and the share constants. This is the debt declared in `odd/tasks/conversations-evidence.md` L6.
- **S6.** Delivery stays as already approved: worktree, ODD doc, observed RED per task, `quick` per iteration, `full` at closure and mandatory because `agent/prompts/*` is a shape surface, then a PR.
